The **pre-master secret** and **master secret** are intermediate cryptographic values generated during the TLS handshake to
create the actual session keys used for encrypting web traffic.

### Pre-Master Secret

The pre-master secret is a temporary, raw piece of secret data generated during the key exchange phase of the handshake.

- **How it's created:** Depending on the key exchange method, it is either generated entirely by the client and encrypted
  using the server's public key (in RSA-based handshakes), or computed jointly by both the client and server using a
  Diffie-Hellman key exchange.
- **Purpose:** It serves as the primary building block from which all other session keys are derived. By itself, it is not
  used to encrypt application data.

### Master Secret

The master secret is a secure, 48-byte value derived by mathematically combining the **pre-master secret** with the **client
random** and **server random** nonces that were exchanged in the initial "Hello" messages of the handshake.

- **Why it matters:** Incorporating the random nonces ensures that even if an attacker manages to figure out the pre-master
  secret, they cannot generate the master secret without knowing the specific random values from that exact session. It also
  prevents replay attacks.
- **Purpose:** The master secret acts as the master seed. Through a Pseudo-Random Function (PRF), the client and server use
  the master secret to generate the actual, symmetric **session keys** (encryption keys, integrity/MAC keys, and
  initialization vectors) used to secure the back-and-forth communication for that specific session.
