**Hostname Check in TLS**

- **Purpose:** Ensures the client is communicating with the correct server, preventing Man-in-the-Middle (MitM) attacks where
  an attacker intercepts traffic using a valid certificate issued for a different domain.
- **Core Mechanism:** During the TLS handshake, the client compares the target domain name (e.g., `api.example.com`) against
  the names listed inside the server's digital certificate.
- **Subject Alternative Name (SAN):** Modern TLS relies heavily on the SAN extension within the certificate, which can list
  multiple hostnames, domain names, and IP addresses that the certificate secures.
- **Common Name (CN):** Historically, the Common Name field in the certificate's subject field was used for verification, but
  it is now deprecated in favor of SAN.
- **Wildcard Matching:** Certificates can include wildcards (such as `*.example.com`), though these typically only cover a
  single subdomain level and follow strict rules defined in RFC 6125.
- **Failure Handling:** If the hostname does not match the certificate's permitted fields, the TLS client immediately aborts
  the connection and displays a security warning or error (such as a certificate name mismatch error).
