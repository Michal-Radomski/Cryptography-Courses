In cryptography, padding is the process of appending extra bytes to a message before encryption so that its total length
becomes an exact multiple of a block cipher's required block size.

### Why Padding is Necessary

Block ciphers like AES process data in fixed-size chunks—typically 16 bytes (128 bits). If a plaintext message is not an
exact multiple of that block size (for example, a 20-byte message), the final block will be incomplete. Without padding, the
cipher cannot process or structure the remaining data.

### PKCS#7 Padding

The industry standard for block cipher padding is **PKCS#7**.

- **How it works:** It fills the remaining space in the final block with bytes that all match the exact number of padding
  bytes added.
- **Example:** If a block size is 16 bytes and the final block has 5 bytes of data, it needs 11 bytes of padding. The
  algorithm appends 11 bytes, each carrying the hexadecimal value `0x0B` (11 in decimal).
- **Full block handling:** If the plaintext is already an exact multiple of the block size, a completely new block filled
  entirely with padding bytes is added. This ensures the receiving system can always unambiguously strip the padding during
  decryption.

### Which Modes Require Padding?

- **Required:** Block modes like **ECB** and **CBC** require explicit padding because they operate strictly on fixed-size
  blocks.
- **Not Required:** Stream or counter modes like **CTR**, **OFB**, and **GCM** do not use padding. They turn the block cipher
  into a stream cipher that encrypts data byte-by-byte, meaning any arbitrary data length is natively supported without
  adjustment.
