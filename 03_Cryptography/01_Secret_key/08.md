# Common Mistakes on IV

Using an Initialization Vector (IV) incorrectly can completely compromise the security of an encrypted message, even if a
strong algorithm like AES and a secure mode like CBC or CTR are used.

### 1. IV Reuse (Nonce Reuse)

Reusing the exact same IV with the same secret key is one of the most catastrophic cryptographic failures.

- **In CTR Mode / Stream Ciphers:** If an IV (often called a nonce in counter modes) is reused, the exact same keystream is
  generated for both messages. An attacker can XOR the two ciphertexts together to cancel out the keystream entirely, leaving
  them with the XOR sum of the two plaintexts, which makes breaking them trivial.
- **In CBC Mode:** Reusing an IV leaks information about the first block of plaintext and allows attackers to detect if
  identical messages were encrypted using the same key.

### 2. Using Predictable or Sequential IVs

An IV does not need to be secret, but it **must be unpredictable** (random or pseudo-random) for most modes. If an attacker
can guess or predict what the next IV will be, they can mount chosen-plaintext attacks or manipulate ciphertext blocks before
they are decrypted.

### 3. Hardcoding the IV

Embedding a static, hardcoded IV directly into source code or configuration files defeats the purpose of dynamic
randomization. Every time the application restarts or encrypts a new file, it will use the same IV, leading directly to IV
reuse vulnerabilities.

### 4. Incorrect IV Length

Each cipher mode expects a precise IV length matching its block size (e.g., 128 bits / 16 bytes for AES). Providing an IV
that is too short, too long, or incorrectly padded can cause the encryption function to fail, truncate data, or introduce
predictable patterns into the process.

### 5. Treating the IV as a Secret Key

An IV is designed to introduce randomness and prevent pattern repetition; it is **not** a secret password. It is meant to be
transmitted alongside the ciphertext (often prepended to it or sent in the clear header) so that the receiver can decrypt the
message. Relying on secrecy for the IV rather than the key is a fundamental architectural flaw.
