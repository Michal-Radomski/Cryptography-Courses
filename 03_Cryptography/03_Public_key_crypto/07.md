Hybrid encryption combines the speed of symmetric encryption (such as AES) with the secure key-exchange capabilities of
asymmetric encryption (such as RSA) to securely transmit large amounts of data.

Symmetric encryption like AES is exceptionally fast and efficient for encrypting large files or messages, but securely
sharing the secret key between parties over an untrusted network is difficult. Asymmetric encryption like RSA solves the key
distribution problem easily, but it is computationally heavy and too slow for large datasets. Hybrid encryption uses both to
leverage the strengths of each.

### How Hybrid Encryption Works (Encryption Side)

When Alice wants to send a secure message or file to Bob:

1. **Generate a Session Key:** Alice's system generates a random, one-time symmetric key for AES (often called a session key
   or data encryption key).
2. **Encrypt the Data:** Alice uses this AES key to encrypt the actual message or file. Because AES is fast, this happens
   almost instantly, even for large files.
3. **Encrypt the Session Key:** Alice takes the AES session key and encrypts it using Bob's RSA **public key**.
4. **Transmit the Package:** Alice sends both the AES-encrypted message and the RSA-encrypted AES key to Bob.

### How Hybrid Encryption Works (Decryption Side)

When Bob receives the package:

1. **Decrypt the Session Key:** Bob uses his RSA **private key** to decrypt the RSA-encrypted AES session key. Because only
   Bob possesses his private key, no one else can recover the session key.
2. **Decrypt the Data:** Bob uses the recovered AES session key to decrypt the main message or file.

### Why This Approach is Standard Practice

Virtually all modern secure communications—including HTTPS/TLS for web browsing, secure messaging apps, and encrypted
email—rely on hybrid encryption. It ensures the performance needed for streaming video or loading web pages while maintaining
the robust cryptographic security required to protect sensitive data in transit.
