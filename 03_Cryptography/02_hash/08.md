A **Message Authentication Code (MAC)** is a cryptographic tool used to verify both the **integrity** and the
**authenticity** of a message.

While a traditional one-way hash function ensures data hasn't been altered, it does not prove _who_ sent it. A MAC solves
this by combining the message with a **secret key** shared only between the sender and the receiver.

### How It Works

1. **Generation:** The sender takes the message and passes it through an algorithm along with a secret cryptographic key,
   producing a short tag (the MAC).
2. **Transmission:** The sender transmits both the original message and the MAC tag to the receiver.
3. **Verification:** The receiver uses the exact same secret key and algorithm on the received message to generate a new MAC
   tag. If their freshly generated tag matches the tag sent by the sender, the receiver knows two things for certain:

- **Integrity:** The message was not tampered with or modified in transit.
- **Authenticity:** The message genuinely originated from someone who possesses the secret key.

### Common Types of MACs

- **HMAC (Hash-based MAC):** Combines a cryptographic hash function (like SHA-256) with a secret key. This is the most widely
  used standard on the internet.
- **CMAC (Cipher-based MAC):** Uses a block cipher (like AES) instead of a hash function to generate the authentication tag.

### Common Use Cases

- **API Security & Web Hooks:** Ensuring requests sent between servers haven't been intercepted or forged.
- **Network Protocols:** Securing data packets in protocols like TLS and SSH alongside encryption.
