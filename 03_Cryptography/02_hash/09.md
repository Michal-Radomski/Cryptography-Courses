A hash length extension attack is a cryptographic vulnerability that affects hash functions built on the **Merkle–Damgård
construction** (such as MD5, SHA-1, and SHA-256) when they are improperly used to create Message Authentication Codes (MACs)
via naive concatenation, such as `Hash(secret + message)`.

### How It Works

The vulnerability stems from the internal mechanics of how Merkle-Damgård hash functions operate:

1. **Internal State:** The hash function processes data in fixed-size blocks. The final hash output is essentially the
   internal state of the algorithm after processing the final block.
2. **State Exposure:** If an attacker intercepts a message and its corresponding hash, that hash value can double as the
   internal state of the hash function.
3. **Forging Extensions:** Because the hash output reveals the internal state, an attacker can feed that state back into the
   algorithm, append arbitrary new data (an "extension"), and correctly compute the padding. This allows them to generate a
   valid hash for a longer message (`message + padding + extension`) **without ever knowing the secret key**.

### The Vulnerable vs. Secure Pattern

- **Vulnerable (Naive Concatenation):** `Token = SHA256(secret_key + message)`
- **Secure (HMAC):** Using **HMAC** (Hash-based Message Authentication Code), which introduces nested key hashing to prevent
  state exposure and length extension entirely: `HMAC(K, message) = Hash((K ⊕ opad) || Hash((K ⊕ ipad) || message))`

### Prevention

- **Never use raw concatenation** like `Hash(secret + message)` for authentication or API tokens.
- **Always use standard HMAC** implementations provided by security libraries (e.g., Python's `hmac` module).
- **Use modern hash algorithms** like **SHA-3**, which use a sponge construction rather than the Merkle–Damgård structure and
  are inherently immune to length extension attacks.
