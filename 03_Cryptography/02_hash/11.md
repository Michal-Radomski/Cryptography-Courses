A **webhook** (sometimes called a web callback or HTTP push API) is a way for one application to send real-time data to
another application whenever a specific event occurs.

### How Webhooks Work

- **Traditional API (Polling):** Your application has to repeatedly ask a server, "Is there any new data? What about now?
  What about now?" This wastes bandwidth and computing resources.
- **Webhook (Event-Driven):** Your application gives another server a URL endpoint and says, "Call this URL whenever
  something happens." When the event triggers (e.g., a payment goes through on Stripe or a push is made to GitHub), that
  server instantly sends an HTTP POST request with the data payload directly to your app.

Think of it like the difference between constantly calling a restaurant to ask if your table is ready (polling) versus giving
them your phone number so they can text you the exact second your table opens up (webhook).

### Why Webhooks Need HMAC

Because webhooks rely on a public URL endpoint that accepts incoming HTTP requests, anyone on the internet could potentially
send fake data to your server pretending to be Stripe or GitHub.

This is why providers use **HMAC signatures**. When they send a webhook, they include a cryptographic signature in the
request headers calculated using a secret key only you and they know. Your server computes its own HMAC of the incoming
payload; if your signature matches theirs, you can trust that the webhook is authentic, secure, and unmodified.
