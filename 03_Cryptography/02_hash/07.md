Salt and pepper are security techniques used in cryptography—specifically in password hashing—to protect user credentials
against advanced cracking methods like rainbow tables and brute-force attacks.

### 1. Salt

A **salt** is a unique, randomly generated string of data added to a user's password before it is passed through a hash
function.

- **How it works:** If two users choose the exact same password (e.g., "password123"), a standard hash function would produce
  the exact same hash for both. A unique salt is generated for _every single user account_ and combined with their password.
- **The Purpose:**
- **Defeats Rainbow Tables:** Attackers use precomputed tables of hashes (rainbow tables) to instantly reverse common hashes.
  Because each salt is unique, precomputed tables become useless.
- **Ensures Unique Hashes:** Identical passwords result in completely different stored hash values across the database.

### 2. Pepper

A **pepper** is a secret piece of data (similar to a cryptographic key) that is added to every password before hashing,
usually applied globally across the entire system.

- **How it works:** Unlike a salt—which is stored publicly in the database alongside the user's hash—a pepper is kept
  strictly secret and stored separately (such as in an environment variable or hardware security module).
- **The Purpose:**
- **Extra Layer of Defense:** If a database is compromised and dumped by an attacker, the salts are leaked along with the
  hashes. However, without the secretly stored pepper, the attacker cannot easily brute-force or crack the password hashes
  offline, because they are missing a crucial piece of the hashing formula.
