A one-way hash function is a mathematical algorithm that takes input data of any size—ranging from a single word to an entire
file—and converts it into a fixed-size string of characters, typically presented as a sequence of numbers and letters.

### Key Characteristics

- **One-Way (Irreversible):** It is mathematically infeasible to reverse the process. Given the output hash, you cannot
  determine the original input data.
- **Deterministic:** The exact same input will _always_ produce the exact same output hash every single time it is run.
- **Fixed Size:** Regardless of how large or small the input is, the output hash is always a constant length (e.g., a SHA-256
  hash is always 256 bits).
- **The Avalanche Effect:** Changing even a single character or bit in the input radically alters the resulting hash output.
- **Collision Resistance:** It is extremely difficult to find two completely different inputs that produce the exact same
  hash output.

### Common Use Cases

- **Password Storage:** Systems store the hash of a user's password rather than the plaintext password. When you log in, the
  system hashes the password you entered and compares it to the stored hash.
- **Data Integrity (Checksums):** Downloading files often comes with an associated hash (like SHA-256). You can hash the
  downloaded file locally; if your hash matches the provider's, the file is complete and uncorrupted.
- **Digital Signatures & Blockchains:** Hash functions link blocks together in a blockchain and create secure digital
  fingerprints for data validation.

### Popular Hash Algorithms

- **MD5 & SHA-1:** Older algorithms that are now considered cryptographically broken and insecure because vulnerabilities
  allow attackers to create "collisions" (different inputs with the same hash).
- **SHA-256 (Secure Hash Algorithm 2):** Widely used and currently considered secure for most modern applications, including
  TLS/SSL and cryptocurrencies.
- **Argon2 / bcrypt:** Specialized hashing algorithms optimized for secure password storage by being deliberately slow to
  compute, preventing brute-force cracking.
