The **One-Time Pad (OTP)**, also known as the Vernam cipher, is a symmetric encryption algorithm that is proven to be
mathematically unbreakable when implemented correctly.

### Core Requirements

For a One-Time Pad to achieve absolute or "perfect secrecy," it must strictly follow four rules:

1. **Randomness:** The key must be generated using a truly random process (such as atmospheric noise or radioactive decay),
   not a pseudorandom computer algorithm.
2. **Length:** The key must be at least as long as the plaintext message being encrypted.
3. **Single Use:** The key must **never** be reused for any other message—hence the name "one-time."
4. **Secrecy:** The key must be shared and kept completely secure by only the sender and the receiver.

### How It Works (XOR Operation)

In modern computing, a One-Time Pad typically uses the binary **XOR (exclusive OR)** operation.

- **Encryption:** The sender converts the plaintext message into binary and combines it bit-by-bit with the random key using
  the XOR operation to produce the ciphertext.

$$\text{Plaintext} \oplus \text{Key} = \text{Ciphertext}$$

- **Decryption:** The receiver takes the ciphertext and combines it with the exact same key using the XOR operation, which
  instantly reverses the process and reveals the original message.

$$\text{Ciphertext} \oplus \text{Key} = \text{Plaintext}$$

### Why It Is Unbreakable

In 1949, mathematician Claude Shannon mathematically proved that the One-Time Pad offers **perfect secrecy**. Because every
possible plaintext message of the same length is equally likely to produce any given ciphertext when combined with a truly
random key, an eavesdropper with infinite computing power cannot determine which message was actually sent. For example, a
ciphertext could decrypt to "ATTACK AT DAWN" or "BUY MORE MILK" depending entirely on which random key is applied. Without
the key, there are no statistical patterns or clues left to analyze.

### Practical Limitations

Despite offering absolute security, the One-Time Pad is rarely used in everyday digital communications due to major
logistical hurdles:

- **Key Distribution:** To send a 1GB file securely, you must first securely exchange a 1GB random key between the sender and
  receiver. If you already have a secure channel capable of sharing a massive key safely, you could just use that channel to
  send the message itself.
- **Key Storage and Management:** Managing, storing, and destroying massive amounts of random keys for continuous
  communication is exceptionally difficult and prone to human error (such as accidental key reuse, which completely destroys
  the security of the cipher).
