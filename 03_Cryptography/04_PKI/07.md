.key, .crt, and .pem are different file formats and extensions used to store cryptographic keys and certificates for SSL/TLS
and other security protocols.

| Extension           | What It Stores            | Secrecy         | Purpose                                                                                                                          |
| ------------------- | ------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **`.key`**          | Private Key               | Strictly Secret | Used by the server to decrypt incoming traffic and prove ownership of the certificate. Must never be shared.                     |
| **`.crt` / `.cer**` | Public Certificate        | Public          | Contains the public key and identity information signed by a Certificate Authority (CA). Shared with clients during a handshake. |
| **`.pem`**          | Container (Keys or Certs) | Varies          | A text-based format (Base64 encoded) that can hold private keys, public certificates, or entire certificate chains.              |

### Detailed Breakdown

- **`.key` Files:** These contain your private cryptographic key. If someone gets access to your `.key` file, they can
  impersonate your server or decrypt your traffic. They usually start with `-----BEGIN PRIVATE KEY-----` or
  `-----BEGIN RSA PRIVATE KEY-----`.
- **`.crt` (or `.cer`) Files:** These contain your public certificate. They are designed to be shared openly with anyone who
  connects to your server. They usually start with `-----BEGIN CERTIFICATE-----`. While often encoded in PEM format under the
  hood, they are saved with a `.crt` extension for clarity.
- **`.pem` Files:** This is a container format (short for Privacy-Enhanced Mail). A single `.pem` file can contain a private
  key, a public certificate, intermediate certificates, or all of them stacked together. Web servers like Nginx and Apache
  frequently accept `.pem` files directly (e.g., a "fullchain.pem" containing your certificate and its intermediate chain).
