To issue a digital certificate, you typically need a **Certificate Authority (CA)**. You can create your own local
(self-signed) CA to issue certificates for testing, development, or internal network use.

Here is how to issue a server certificate using OpenSSL in a few simple steps:

---

### Step 1: Create a Private Key for your CA

First, generate a private key for your Certificate Authority:

```bash
openssl genrsa -out ca.key 2048

```

### Step 2: Create the Root CA Certificate

Use the private key to create a self-signed root certificate (`ca.crt`) valid for 365 days:

```bash
openssl req -x509 -new -nodes -key ca.key -sha256 -days 365 -out ca.crt -subj "/CN=MyLocalRootCA"

```

### Step 3: Create a Private Key for the Server/Website

Generate a private key for the specific server or domain you want to secure:

```bash
openssl genrsa -out server.key 2048

```

### Step 4: Create a Certificate Signing Request (CSR)

Generate a CSR for the server using its private key. The Common Name (`CN`) should match your website domain or IP address
(e.g., `localhost` or `example.local`):

```bash
openssl req -new -key server.key -out server.csr -subj "/CN=localhost"

```

### Step 5: Issue (Sign) the Server Certificate using your CA

Finally, use your CA's key and certificate to sign the server's CSR, issuing the final server certificate (`server.crt`):

```bash
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out server.crt -days 365 -sha256

```

### Result:

You now have `server.crt` (the issued certificate) and `server.key` (the server's private key), which you can install on a
web server (like Nginx or Apache) to enable HTTPS. To make your browser trust it without warning, you would import `ca.crt`
into your operating system's **Trusted Root Certification Authorities** store.
