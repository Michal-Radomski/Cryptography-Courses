Securing a web server using a public key certificate (commonly known as an SSL/TLS certificate) involves encrypting the
traffic between a user's browser and your server to protect data in transit.

Here is the standard process to set up a secure web server:

1. **Obtain an SSL/TLS Certificate**

- **Free/Automated:** Use a trusted Certificate Authority (CA) like **Let's Encrypt** via tools like Certbot to automatically
  generate and renew certificates.
- **Paid/Commercial:** Purchase a certificate from a commercial CA (like DigiCert or Sectigo) if you need extended validation
  or organizational backing.
- **Self-Signed:** Generate your own certificate using OpenSSL for local testing or internal networks (though browsers will
  show a security warning to external users).

2. **Configure Your Web Server** Install and point your web server configuration to the three essential files: your public
   certificate, your private key, and the CA bundle (intermediate certificate).

- **Nginx Example:**

```nginx
server {
    listen 443 ssl;
    server_name example.com;

    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    # Modern security settings
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
}

```

- **Apache Example:**

```apache
<VirtualHost *:443>
    ServerName example.com
    SSLEngine on
    SSLCertificateFile "/path/to/cert.pem"
    SSLCertificateKeyFile "/path/to/key.pem"
    SSLCertificateChainFile "/path/to/chain.pem"
</VirtualHost>

```

3. **Force HTTPS Redirection** Configure your server to automatically redirect all incoming HTTP traffic (port 80) to HTTPS
   (port 443) to ensure users always connect securely.
4. **Test Your Configuration** Use tools like the **SSL Labs SSL Server Test** to check your server for vulnerabilities,
   proper cipher suites, and correct certificate chain installation.
