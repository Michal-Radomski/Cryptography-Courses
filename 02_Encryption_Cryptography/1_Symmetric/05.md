Symmetric encryption for secure data storage protects data at rest—such as files on a hard drive, rows in a database, or
objects in cloud storage—by transforming plaintext into ciphertext using a secret key, ensuring that unauthorized actors
cannot read the data even if physical media or server access is compromised.

### Recommended Algorithms and Modes for Storage

- **XTS-AES (Xor-Ciphertext-Stealing):** The standard mode for full-disk encryption and block-level storage systems (such as
  BitLocker, LUKS, and macOS FileVault). It is specifically designed to handle sector-based storage securely, preventing data
  manipulation and cut-and-paste attacks across blocks.
- **AES-256-GCM:** The preferred choice for databases, application-level file encryption, and cloud object storage. It
  provides authenticated encryption (AEAD), ensuring that stored data cannot be silently modified or corrupted without
  detection.

### Core Architecture for Secure Data Storage

- **Envelope Encryption:** A multi-tier architecture where a local Data Encryption Key (DEK) encrypts the actual files or
  database fields, and a separate Key Encryption Key (KEK) managed by a secure service encrypts the DEK. This minimizes the
  risk profile if individual data records are exposed.
- **Unique Initialization Vectors (IVs):** Every time a file or database record is saved or updated, a unique, unpredictable
  IV or nonce must be generated. Reusing an IV with the same symmetric key leaks structural patterns in stored data.
- **Separation of Keys and Data:** Encryption keys must never be stored alongside the data they protect. Production
  environments rely on dedicated Hardware Security Modules (HSMs) or cloud Key Management Services (KMS) with strict access
  controls and automatic key rotation policies.
