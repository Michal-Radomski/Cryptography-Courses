Symmetric encryption is the foundational method for bulk data transfer because it is computationally efficient and fast
enough to process large volumes of data, whereas asymmetric encryption (like RSA) is too resource-intensive for large files
or continuous streams.

When securing bulk data—such as file transfers, database backups, or video streams—specific algorithms and modes are chosen
to maximize throughput while maintaining security and integrity.

### Recommended Algorithms and Modes

- **AES-GCM (Galois/Counter Mode):** The gold standard for modern bulk data transfer. GCM is an Authenticated Encryption with
  Associated Data (AEAD) mode, meaning it simultaneously encrypts the data and provides cryptographic integrity to prevent
  tampering or bit-flipping attacks. It also supports hardware acceleration (via AES-NI instructions found in most modern
  CPUs), allowing it to encrypt gigabytes per second.
- **ChaCha20-Poly1305:** A high-speed stream cipher paired with an authenticator, frequently used as an alternative to
  AES-GCM. It is exceptionally fast on mobile devices, ARM processors, and hardware that lacks dedicated AES instructions.
- **AES-CBC with HMAC:** A traditional approach where Cipher Block Chaining provides confidentiality and a Hash-based Message
  Authentication Code ensures integrity. While widely deployed, it requires careful implementation to avoid padding oracle
  vulnerabilities and is largely being succeeded by GCM.

### Architecture of Bulk Encryption

Because symmetric encryption requires both parties to share the same secret key, secure bulk data transfer typically relies
on a **hybrid encryption model**:

1. **Key Exchange:** The sender and receiver use an asymmetric key exchange protocol (such as Elliptic-Curve Diffie-Hellman
   or RSA) to securely negotiate a temporary, session-specific symmetric key.
2. **Bulk Transfer:** Once the symmetric key is established, the heavy lifting begins. The system encrypts the bulk data
   using a fast symmetric cipher (like AES-256-GCM) under that session key.
3. **Session Termination:** The symmetric key is discarded after the transfer is complete, ensuring forward secrecy so that
   future compromises of long-term keys do not expose past transfers.
