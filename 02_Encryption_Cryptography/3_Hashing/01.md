Cryptographic hash functions take an input of any size and convert it into a fixed-size string of characters (a digest) that
is unique to that input. They are deterministic, one-way, and highly sensitive to minor modifications in the source data.

### MD5 (Message-Digest Algorithm 5)

- **Output Size:** 128-bit
- **Security Status:** **Broken**
- **Overview:** Designed in 1991, MD5 was widely used for file checksums and data integrity. However, critical
  vulnerabilities allow attackers to generate collisions (two different inputs producing the same hash) within seconds. It
  should never be used for security-sensitive purposes.

### SHA-1 (Secure Hash Algorithm 1)

- **Output Size:** 160-bit
- **Security Status:** **Broken**
- **Overview:** Developed by the NSA and released in 1995, SHA-1 was a standard for digital signatures and certificates.
  Practical collision attacks (such as the SHAttered attack) rendered it insecure, leading to its deprecation across modern
  web browsers and security protocols.

### SHA-2 (Secure Hash Algorithm 2)

- **Output Size:** 224, 256, 384, or 512 bits
- **Security Status:** **Secure**
- **Overview:** Introduced in 2001, SHA-2 includes variants like **SHA-256** and **SHA-512**. SHA-256 is currently the
  industry workhorse, forming the backbone of TLS, digital certificates, code signing, and blockchain technologies. No
  practical collision attacks have been demonstrated against it.

### SHA-3 (Secure Hash Algorithm 3)

- **Output Size:** Variable (224, 256, 384, 512 bits, or customizable via SHAKE)
- **Security Status:** **Secure**
- **Overview:** Standardized by NIST in 2015, SHA-3 is based on the Keccak algorithm. While it shares identical output
  lengths with SHA-2, it uses a completely different internal structure (the sponge construction), serving as a robust
  alternative and future-proofing option against potential cryptographic weaknesses in SHA-2.

### Specialized Password Hash Functions (Bcrypt & Argon2)

- **Output Size:** Variable/Configurable
- **Security Status:** **Secure** (Recommended)
- **Overview:** General-purpose fast hashes like SHA-256 process billions of calculations per second, making them vulnerable
  to brute-force attacks if used for passwords. Purpose-built algorithms like **bcrypt** and **Argon2** (the winner of the
  Password Hashing Competition) are deliberately designed to be slow and memory-hard, protecting user credentials against
  massive parallel cracking attempts.
