Cryptographic hash functions ensure data integrity by generating a unique, fixed-size fingerprint—known as a hash or
digest—for any given file or dataset, making it immediately obvious if even a single bit of the data has been altered.

### Key Properties for Data Integrity

- **Deterministic:** The exact same input data will always produce the exact same hash output every single time it is
  processed.
- **Avalanche Effect:** Altering even a single bit or character in the input data drastically and unpredictably changes the
  resulting hash output.
- **Collision Resistance:** It is computationally infeasible for an attacker to find two different inputs that produce the
  exact same hash value.
- **One-Way (Pre-image) Function:** A hash can be easily computed from the data, but it is impossible to reverse the process
  to reconstruct the original data from the hash alone.

### Common Applications

- **Software Downloads and Checksums:** Software developers publish the SHA-256 hash of their installer files on their
  websites. After downloading a program, users can run a local hashing tool to verify that their downloaded copy matches the
  official hash, confirming the file is authentic and hasn't been corrupted or maliciously modified in transit.
- **Version Control Systems (Git):** Git uses cryptographic hashes to uniquely identify every commit, file tree, and snapshot
  in a repository's history, ensuring that past code changes cannot be secretly tampered with.
- **Digital Signatures:** To sign a large document or software package, systems typically hash the file first and then
  digitally sign only the small hash value. This guarantees integrity while saving significant computational overhead.
