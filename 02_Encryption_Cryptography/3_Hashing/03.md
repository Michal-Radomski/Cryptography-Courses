Password security relies on specialized cryptographic hash functions designed to protect user credentials against modern
brute-force and dictionary attacks.

Unlike general-purpose hashes (like SHA-256) which are intentionally optimized for blazing-fast computation, password hash
functions are engineered to be deliberately slow and resource-intensive. This design drastically slows down an attacker's
ability to guess passwords using massive parallel processing or specialized hardware like GPUs.

### Key Concepts in Password Hashing

- **Salting:** A unique, random string added to each password before it is hashed. Salting ensures that identical passwords
  produce completely different hash outputs, rendering precomputed lookup tables (rainbow tables) useless.
- **Work Factor (Cost):** A configurable parameter that controls how much CPU time, memory, or processing power is required
  to compute a single hash. As computer hardware gets faster, the work factor can be increased to maintain security.

### Core Password Hashing Algorithms

- **PBKDF2 (Password-Based Key Derivation Function 2):** A widely adopted standard that applies a pseudorandom function (like
  HMAC-SHA-256) alongside a salt and a user-defined iteration count. While historically standard, it is vulnerable to
  optimization via specialized hardware (GPUs and ASICs) because it has low memory overhead.
- **Bcrypt:** Based on the Blowfish cipher, bcrypt incorporates a tunable cost factor and natively integrates a salt into the
  hash output. It has been a long-standing industry standard for securely storing web application passwords.
- **scrypt:** Designed to be memory-hard, scrypt requires large amounts of RAM to compute in addition to CPU cycles. This
  design heavily penalizes attackers trying to run parallel cracking operations on specialized hardware like custom ASIC
  rigs.
- **Argon2:** The winner of the 2015 Password Hashing Competition, Argon2 is the current gold standard for password hashing.
  It offers multiple variants (Argon2i for side-channel resistance, Argon2d for GPU-resistance, and Argon2id as a hybrid
  default) and allows precise tuning of memory consumption, CPU threads, and time cost.
