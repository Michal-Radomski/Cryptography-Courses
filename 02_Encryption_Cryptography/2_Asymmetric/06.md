Asymmetric cryptography is frequently used for secure key sharing—a technique known as a **hybrid cryptosystem**—to combine
the high speed of symmetric encryption with the secure key distribution of asymmetric cryptography.

### Why Hybrid Encryption is Needed

Symmetric encryption algorithms (like AES) are computationally efficient and ideal for encrypting large volumes of data, but
securely sharing the secret symmetric key between two parties over an unencrypted network is difficult. Asymmetric encryption
(like RSA or Elliptic Curve Cryptography) solves the key distribution problem without requiring a pre-shared secret, but it
is slow and computationally expensive for large data streams.

### How Asymmetric Key Sharing Works

1. **Key Generation:** The receiver generates an asymmetric public/private key pair and shares their public key with the
   sender.
2. **Session Key Generation:** The sender generates a random, temporary symmetric key (often called a session key) to encrypt
   the actual message data.
3. **Key Encryption:** The sender uses the receiver's **public key** to encrypt the symmetric session key.
4. **Transmission:** The sender transmits both the symmetrically encrypted data and the asynchronously encrypted session key
   to the receiver over the network.
5. **Decryption:** The receiver uses their **private key** to decrypt the session key, and then uses that recovered session
   key to decrypt the main body of data.

This combined approach ensures that the bulk data remains secure, the symmetric key is safely transported across public
networks, and the system performs efficiently under heavy traffic—forming the backbone of protocols like TLS/HTTPS that
secure everyday web browsing.
