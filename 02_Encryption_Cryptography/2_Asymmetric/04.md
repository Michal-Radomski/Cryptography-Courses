The Diffie-Hellman key exchange is a cryptographic protocol that allows two parties to establish a shared secret over an
insecure public channel without transmitting the secret itself.

The protocol relies on modular arithmetic and the computational difficulty of the discrete logarithm problem. The process
follows these steps:

### 1. Public Setup

Alice and Bob publicly agree on two numbers:

- A large prime number, $p$
- A base generator, $g$ (a primitive root modulo $p$)

### 2. Private Key Generation

- Alice chooses a secret private key, $a$.
- Bob chooses a secret private key, $b$.

### 3. Public Value Exchange

- Alice computes her public value $A$ using her private key:

$$A \equiv g^a \pmod p$$

She sends $A$ to Bob.

- Bob computes his public value $B$ using his private key:

$$B \equiv g^b \pmod p$$

He sends $B$ to Alice.

### 4. Shared Secret Computation

- Alice receives $B$ and computes the shared secret $s$ using her private key $a$:

$$s \equiv B^a \pmod p$$

- Bob receives $A$ and computes the shared secret $s$ using his private key $b$:

$$s \equiv A^b \pmod p$$

Because of the properties of modular exponentiation, both computations yield the exact same result:

$$(g^b)^a \equiv (g^a)^b \equiv g^{ab} \pmod p$$

Alice and Bob now share a secret key $s$ that they can use for symmetric encryption, while an eavesdropper listening in on
the public channel only sees $p$, $g$, $A$, and $B$. Calculating the shared secret directly from these public values requires
solving the discrete logarithm problem, which is computationally infeasible for large numbers.
