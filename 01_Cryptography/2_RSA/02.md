You can implement RSA encryption and decryption in Node.js using the built-in `crypto` module. Because RSA is an asymmetric
algorithm, you generate a key pair: a public key to encrypt data and a private key to decrypt it.

Here is a complete, practical example of how to generate RSA keys and perform encryption and decryption in Node.js:

```javascript
const crypto = require("crypto");

// 1. Generate an RSA Key Pair (Typically 2048 or 4096 bits)
const { publicKey, privateKey } = crypto.generateKeyPairSync("rsa", {
  modulusLength: 2048,
  publicKeyEncoding: {
    type: "spki",
    format: "pem",
  },
  privateKeyEncoding: {
    type: "pkcs8",
    format: "pem",
  },
});

const sampleText = "Hello, this is a secure message using RSA!";
console.log("Original Text:", sampleText);

// 2. Encrypt the data using the PUBLIC key
// Note: RSA is typically used for small amounts of data (like session keys), not large files.
const encryptedData = crypto.publicEncrypt(
  {
    key: publicKey,
    padding: crypto.constants.RSA_PKCS1_OAEP_PADDING,
    oaepHash: "sha256",
  },
  Buffer.from(sampleText, "utf8")
);

console.log("\nEncrypted Data (Base64):", encryptedData.toString("base64"));

// 3. Decrypt the data using the PRIVATE key
const decryptedData = crypto.privateDecrypt(
  {
    key: privateKey,
    padding: crypto.constants.RSA_PKCS1_OAEP_PADDING,
    oaepHash: "sha256",
  },
  encryptedData
);

console.log("\nDecrypted Text:", decryptedData.toString("utf8"));
```

### Best Practices for RSA:

- **Padding:** Always use secure padding like **OAEP** (`crypto.constants.RSA_PKCS1_OAEP_PADDING`) rather than older padding
  schemes like PKCS#1 v1.5, which can be vulnerable to padding oracle attacks.
- **Data Size Limit:** RSA can only encrypt data that is smaller than the key size itself (minus padding overhead). For
  encrypting large messages or files, use RSA to securely share a temporary AES key (hybrid encryption), and then use AES for
  the bulk data.
