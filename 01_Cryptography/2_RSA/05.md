## Storing and Exchanging RSA Keys with X.509 Certificates

While raw RSA public and private keys can be shared as text strings (like the PEM formats we looked at), managing them
securely in enterprise systems, websites, and APIs requires a standardized structure. This is where **X.509 certificates**
come in.

---

### What is an X.509 Certificate?

An X.509 certificate is a digital document that securely binds a cryptographic **public key** to a specific identity (such as
a domain name, organization, or individual). It allows users or servers to trust that a public key actually belongs to who
they claim to be.

An X.509 certificate typically includes:

- **The Public Key:** The RSA public key itself.
- **Subject Information:** Details about the owner (e.g., Common Name like `example.com`, organization, country).
- **Issuer Information:** Details about the **Certificate Authority (CA)** that verified the identity and signed the
  certificate.
- **Validity Period:** Start and expiration dates.
- **Digital Signature:** A signature created by the CA using _their_ private key, proving the certificate hasn't been
  tampered with.

---

### How Certificates Enable Trust (The Chain of Trust)

When your browser visits an HTTPS website, the server presents its X.509 certificate.

1. Your browser checks the certificate's **digital signature** against a pre-installed list of trusted root Certificates
   Authorities (like Let's Encrypt, DigiCert, etc.).
2. If the signature is valid and the certificate hasn't expired, your browser trusts the public key provided inside the
   certificate.
3. It then uses that public key to securely handshake and establish an encrypted session.

---

### Storing Private Keys Securely

While public keys are meant to be shared openly inside certificates, **private keys must never leave secure storage**. In
professional environments, private keys are stored in:

- **Hardware Security Modules (HSMs):** Dedicated physical crypto processors.
- **Environment Variables / Secret Managers:** Encrypted cloud storage (like AWS Secrets Manager or HashiCorp Vault) rather
  than hardcoded in source code files.
- **Encrypted PEM Files:** Protected with a strong passphrase.
