## Overview of Secure Boot

**Secure Boot** is a security standard developed by the PC industry (part of the UEFI specification) designed to ensure that
a device boots using only software that is trusted by the manufacturer.

Building directly on the concept of the **Root of Trust**, Secure Boot prevents unauthorized, malicious software—such as
rootkits, bootkits, or modified operating systems—from taking over your computer during the startup process.

---

### How Secure Boot Works

When you power on your computer, the motherboard's UEFI firmware performs a cryptographic check before handing over control:

1. **Checking Signatures:** The firmware checks the digital signature of the bootloader (the first piece of software loaded
   to start the OS) against a built-in database of trusted public keys (stored in the motherboard's NVRAM).
2. **Validating Trust:** If the signature matches a trusted certificate (usually provided by Microsoft or the hardware
   vendor), the bootloader is allowed to run.
3. **Halting Unauthorized Code:** If the signature is invalid, missing, or untrusted, Secure Boot halts the process and
   refuses to boot, protecting the system from compromised software.

---

### How Windows Uses Secure Boot

Windows has integrated Secure Boot deeply into its architecture since Windows 8:

- **Default Enforcement:** Modern Windows PCs come with Secure Boot enabled by default.
- **Microsoft Keys:** The motherboard firmware contains Microsoft's public keys. Windows bootloaders and kernel drivers must
  be cryptographically signed using certificates backed by these keys.
- **Driver Integrity:** Secure Boot extends beyond just the bootloader; it also helps ensure that early-startup drivers
  loaded by Windows are properly signed, preventing low-level malware from inserting itself into the system core.

---

### How Ubuntu Uses Secure Boot

Because Linux distributions are open-source and independent of Microsoft, supporting Secure Boot required a clever solution
so that users wouldn't be locked out of running Linux:

- **The Shim Loader:** Ubuntu uses a small, trusted bootloader called **`shim`**. The `shim` is signed by a certificate that
  the motherboard's UEFI firmware already trusts (typically Microsoft's third-party UEFI certificate authority).
- **Chain of Trust:** When you boot Ubuntu, the UEFI firmware trusts and launches the `shim`. The `shim` then verifies and
  launches the secondary bootloader (**GRUB**), which in turn verifies and launches the **Linux kernel**.
- **Custom Modules:** If you need to load proprietary kernel modules (like certain NVIDIA graphics drivers) on an Ubuntu
  system with Secure Boot enabled, Ubuntu provides tools to enroll your own local keys so the system can verify them safely.
