## Step-by-Step Breakdown of the SHA Algorithm (SHA-256)

While cryptographic hash algorithms involve complex mathematics behind the scenes, we can break down how **SHA-256**
processes data into seven logical steps.

---

### Step 1: Padding the Message

Before hashing begins, the original input data (message or file) must be padded so that its total length is a specific
multiple.

- A single "1" bit is appended to the end of the message.
- A series of "0" bits are added after it until the message length is 64 bits shy of a multiple of 512 bits (specifically,
  $448 \pmod{512}$).

### Step 2: Appending Length

A 64-bit block representing the **original length** of the message (before padding) is added to the very end of the padded
message. This ensures that the total bit length is now an exact multiple of 512 bits.

### Step 3: Parsing the Message into Blocks

The fully padded message is divided into sequential **512-bit blocks**. If a file is large, it is broken down into multiple
512-bit chunks, which will be processed one by one.

### Step 4: Setting Up Initial Hash Values (Constants)

SHA-256 uses eight initial 32-bit working variables (often called $A$ through $H$).

- These values are derived from the fractional parts of the square roots of the first eight prime numbers
  ($2, 3, 5, 7, 11, 13, 17,$ and $19$). These act as the starting baseline for the hash calculation.

### Step 5: Preparing the Message Schedule

For each 512-bit block, the data is further divided into sixteen 32-bit words.

- The algorithm then expands these 16 words into **64 total words** using specific bitwise operations (shifting and rotating
  bits). This ensures that every part of the block influences the final outcome.

### Step 6: The Compression Loop (64 Rounds)

This is the core engine of the algorithm. For 64 rounds, the algorithm mixes the 64 message words with the working variables
($A$ through $H$) and a set of mathematical constants derived from the cube roots of the first 64 prime numbers.

- During each round, complex logical functions (like bitwise AND, XOR, and ROTATE) blend the data together, changing the
  working variables drastically.

### Step 7: Generating the Final Hash

After all 512-bit blocks have passed through the 64-round compression loop, the final values of the working variables are
combined to produce the **256-bit hash output** (usually represented as a 64-character hexadecimal string).

---

Because of this intricate, multi-layered mixing process, changing even a single bit in the original input causes a completely
unpredictable chain reaction, resulting in a totally different final hash (the avalanche effect).

## Breaking Down SHA Padding and Modulo Arithmetic

When preparing a message to be hashed by SHA-256, the algorithm needs the data to fit neatly into chunks (blocks) of a
specific size. Here is a plain-English translation of that padding rule:

---

### 1. The Goal: Leaving Room for the Length Tag

SHA-256 processes data in **512-bit blocks**. At the very end of the final block, the algorithm always reserves **64 bits**
to store a number representing the _original_ length of the message.

Because 64 bits are reserved at the end, the data right before it can only occupy the remaining space in that 512-bit block:

$$512 - 64 = 448\text{ bits}$$

Therefore, before adding that 64-bit length tag, the padded message must be stopped exactly **64 bits shy** of a full 512-bit
block—meaning its length must be **448 bits** (or a multiple of 512 plus 448 bits).

---

### 2. Understanding $(448 \pmod{512})$

The notation $448 \pmod{512}$ uses modular arithmetic, which deals with remainders after division:

- **$\pmod{512}$** means "divide the total number of bits by 512 and look at the remainder."
- **$= 448$** means "the remainder left over must always be 448."

#### Example:

- If your message length divided by 512 leaves a remainder of 448, it is perfectly sized.
- If it leaves a smaller remainder, the algorithm tacks on a single `"1"` bit, fills the rest of the space with `"0"` bits
  until the remainder is exactly 448, and _then_ tacks on the 64-bit length tag to make the total block a clean multiple
  of 512.
