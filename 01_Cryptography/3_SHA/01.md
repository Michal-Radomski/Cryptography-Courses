## Overview of SHA (Secure Hash Algorithm)

**SHA** stands for **Secure Hash Algorithm**. It is a family of cryptographic hash functions designed by the National
Institute of Standards and Technology (NIST) and published as U.S. Federal Information Processing Standards (FIPS).

Unlike encryption algorithms (which are designed to be reversible with a key), hash functions are **one-way mathematical
operations**. They take an input of any size (a password, a file, or a message) and convert it into a fixed-size string of
characters, commonly called a "hash" or "digest."

---

### Core Characteristics of SHA

- **Fixed Output Size:** Regardless of whether the input is a single word or a massive 10GB video file, the resulting hash
  will always be the exact same length (e.g., 256 bits for SHA-256).
- **The Avalanche Effect:** If you change even a single character or bit in the input data, the resulting hash changes
  drastically and unpredictably.
- **One-Way Function:** It is computationally impossible to reverse a hash to find out what the original input data was.
- **Collision Resistance:** It is virtually impossible for two completely different inputs to produce the exact same hash
  output.

---

### Main Members of the SHA Family

- **SHA-1:** An older 160-bit hashing algorithm. It has since been proven cryptographically broken because researchers found
  vulnerabilities allowing collisions (two different files producing the same hash). It is no longer considered secure and is
  deprecated in modern systems.
- **SHA-2 (including SHA-256 and SHA-512):** The current widely trusted industry standard. SHA-256 generates a 256-bit hash
  and is heavily used in TLS/HTTPS certificates, digital signatures, secure password hashing, and blockchain technology.
- **SHA-3:** The newest member of the hash family. While it produces outputs of the same lengths as SHA-2, it uses a
  completely different internal structure (called a sponge construction) to provide an alternative defense layer against
  potential future cryptographic attacks.

---

### Common Use Cases

- **Data Integrity:** Verifying that a downloaded software file or update hasn't been corrupted or altered in transit by
  comparing its hash against the publisher's official hash.
- **Password Hashing:** Storing secure hashes of user passwords in databases rather than plain text, ensuring that even if a
  database is breached, user passwords remain protected.
- **Digital Signatures:** Helping secure communications and authentication tokens across the internet.
