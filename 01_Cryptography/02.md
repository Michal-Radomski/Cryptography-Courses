In symmetric cryptography (where the same key is used to both encrypt and decrypt data), encryption algorithms generally fall
into two main categories: **block ciphers** and **stream ciphers**.

Here is how they work and how they differ:

---

## 1. Block Ciphers

A **block cipher** takes data in fixed-size chunks—called **blocks**—and encrypts them one block at a time.

- **How it works:** If a block size is 128 bits, the algorithm takes 128 bits of plaintext, scrambles it using the key and a
  complex mathematical function, and outputs 128 bits of ciphertext. If your data doesn't fit neatly into blocks, it gets
  padded (filled out with extra data) until it does.
- **Common Example:** **AES (Advanced Encryption Standard)**, which is the global standard used to secure everything from
  Wi-Fi networks to encrypted messaging apps and secure files.
- **Analogy:** Think of a block cipher like a locker room. You place items into individual lockboxes (blocks), lock each one
  individually, and then send them off.

---

## 2. Stream Ciphers

A **stream cipher** encrypts data continuously—one digital bit or byte at a time—rather than waiting for a full block to
accumulate.

- **How it works:** The cipher combines a secret key with a pseudorandom number generator (called a keystream) to produce a
  continuous stream of bits. This keystream is then mixed with the plaintext (usually using an XOR operation) to create the
  ciphertext.
- **Common Examples:** **ChaCha20** (often used alongside AES in modern web traffic and mobile devices) and **RC4** (older
  and mostly deprecated due to security flaws).
- **Analogy:** Think of a stream cipher like mixing paint color into a steady, flowing stream of water. Every drop of water
  (data) gets altered immediately as it flows past.

---

## Key Differences at a Glance

| Feature                | Block Cipher                                                                                | Stream Cipher                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| **Unit of Processing** | Fixed-size blocks (e.g., 64 or 128 bits)                                                    | Continuous stream (bit by bit or byte by byte)                              |
| **Speed & Memory**     | Typically requires more memory and processing power to handle padding and block management. | Generally faster and uses less memory, making it ideal for real-time data.  |
| **Primary Use Cases**  | Secure file storage, database encryption, and secure network protocols (like TLS).          | Real-time communications, video streaming, and wireless network encryption. |
